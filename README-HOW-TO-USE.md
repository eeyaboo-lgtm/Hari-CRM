# How to use this folder

These are starter files distilled from real work on Dino History World (and Coco's brother
Arun's professional SEO process, added 2026-08-07). Copy them into any new project so it
starts with a working ruleset instead of a blank page.

## Setup for a new project

1. Copy all four files into the new project's root folder:
   - `CLAUDE.md` — standing rules: coding standards, revenue-first product thinking, the SEO &
     Content Playbook, and the Multi-AI Memory & Handoff Habits convention.
   - `AGENTS.md` — the entry-point doc any AI tool should read first.
   - `CONTENT-STYLE.md` — anti-AI-detection writing rules + sourcing rules, for any project
     that publishes text content.
   - `SEO-STRATEGY-STARTER.md` — rename to `SEO-STRATEGY.md` once you start filling it in.
2. Fill in every `[bracketed placeholder]` in `CLAUDE.md`'s Purpose section and Technical
   Preferences, and in `AGENTS.md`'s "What this project is" / "Stack" / "Environment gotchas"
   sections. Delete the `*Template...*` footer lines once done.
3. If the project won't publish content/SEO-driven pages, `CONTENT-STYLE.md` and
   `SEO-STRATEGY-STARTER.md` can be skipped — everything else still applies.
4. Tell whichever AI tool you're using to read `AGENTS.md` first at the start of a session.
   That's the whole point of the convention: any tool, same starting context, no re-explaining.

## Why this exists

Rebuilding rules and context from scratch every new project wastes the exact thing these docs
are meant to save: time and consistency. This folder is the reusable core — the founder/product
rules, the SEO checklist that took a real professional's process to compile, and the habit of
writing decisions into shared files instead of a private memory only one AI tool can see.

## Keeping it current

If a new rule, correction, or piece of hard-won process knowledge comes out of a project (the
way today's SEO playbook came out of a call with Arun), fold the generic, project-agnostic
version of it back into these template files — not just the live project's copy — so the next
project inherits it too.
